# Design system

Reclaim's semantic CSS tokens live in `src/theme.css`. Components use shared surface, text, border, accent, spacing, radius, shadow, and control tokens. Light is the default presentation; light, dark, and system preferences are saved in SQLite.

Core neutral tokens (surfaces, text, and borders in both themes) derive from the organization brand color through `color-mix` over hue-neutral anchors, so choosing an organization color themes the entire app rather than only accent-filled controls. The two elevated surfaces (`--surface-primary`, `--surface-raised`) stay pure white in light theme so content floats on the brand-tinted canvas; the curated categorical accents (sand/blue/green/rose/violet/peach), state colors, overlays, shadows, glass surfaces, and the decorative setup border remain brand-independent literals. Derivation weights reproduce the original green palette exactly when the default brand color is set. The light token block also matches `[data-theme="system"]` shells, which fixed a defect where an organization color had no effect for system-theme workspaces on a light-mode OS (custom properties resolved at `:root` scope, before the shell-level brand variable existed).

The desktop frame uses persistent left navigation, compact topbar, content region, and contextual item drawer. Forms use shared field components and explicit labels; buttons have primary, secondary, quiet, and icon variants. Status and secure-storage indicators combine text with color. Responsive rules adapt navigation, grids, and forms for narrower windows. Reduced-motion preferences are respected and interactive controls have focus-visible styling.

Region sizing rules that follow from the 2026-11-06 layout repairs and their 2026-11-08 revisions: the app shell is a bounded 100vh column — topbar, page heading, and statusbar are fixed chrome, and views render inside `.view-region`, the only page-level scroll container — so scrolling never moves the navigation context. The Overview is height-budgeted (condensed metric cards, height-capped summary panels whose table/report regions scroll internally, gallery as the flexible region, quick actions anchored at the bottom) so it fits common desktop window heights without page scrolling; data-table views fill the available height and scroll their list regions internally with consistent row heights, and shorter windows degrade to region scrolling rather than clipping. The item drawer is a fixed-height column with three zones — a sticky header carrying the identity facts (name, category, reference, status), a single bounded scrolling body (photos, details, custody history with its own capped internal scroll so a long history cannot dominate the body), and a pinned footer with the custody actions always reachable; this supersedes the original whole-drawer-scroll repair, whose failure mode (a flex-squashed invisible scroll container) is now avoided by making the body the one scroll container with `min-height: 0`. Dashboard quick-action tracks use `minmax(0,1fr)` with wrapping labels, inventory toolbar controls wrap to a second row rather than clipping behind the panel edge, and lost-report actions are explicitly placed in the content columns at narrow widths. Operation feedback uses `inline-status` for success and `inline-alert` for errors, each with a matching `role`.

New UI should use semantic tokens rather than one-off color values and should preserve predictable headings, descriptions, and action alignment. Avoid using color alone to convey a status. Organization branding includes a persisted logo and an accessible primary color that themes the whole workspace through the derived neutral tokens. Onboarding and the main shell share a stored theme preference; Follow System uses OS preference CSS.

Text defaults to a 12 px minimum and uses a persisted interface-size preference. The small-A and large-A controls are in the top-right of setup and the main workspace; they adjust text and primary control targets and remain keyboard-operable with explicit accessible names.

Run `pnpm check:design` before merging UI changes. It scans component CSS and TS/TSX for unapproved color literals, while allowing `src/theme.css` to define semantic theme values and `src/theme-palette.ts` to define the curated organization palette. It also applies a heuristic check to JSX buttons and form controls for an explicit accessible name, text content, or wrapping label. This caught an unlabeled storage-message dismiss button; it now has a contextual accessible name. The check does not calculate computed accessible names, inspect screenshots, establish rendered contrast, or replace the visual qualification matrix in `docs/release-readiness.md`.

Run `pnpm check:contrast` for the token-level WCAG contrast checks. Because core neutrals are brand-derived, the script resolves every brand-mixed token for each curated organization color and checks text/surface pairs, field placeholders, status text, brand and hover fills — including text on the brand-tinted `--brand-soft` selected-item surface — and focus-indicator contrast per brand: 410 token pairs across light, dark, and the five curated brands. The script also fails if a core neutral stops deriving from the organization brand color. With the default brand color the derived values match the previously audited literals, so the 2026-11-07 rendered axe sweep and its measured minima remain the rendered baseline; the token-level minimum for the tightest pairs (light warning text on brand-tinted surfaces) is 4.5:1 by construction of the check. White or dark text on curated brand fills and focus rings pass the script's thresholds in both themes. An axe-core rendered sweep across 70 screen/theme scans (2026-11-07) reports zero violations at every severity; see `docs/testing.md` for the fixed findings.

Disabled text remains intentionally subdued. The check does not include disabled content, photo overlays, user-provided colors, every rendered component/background pairing, native dialog chrome, screenshots at all scales, or assistive-technology output. Keep the full rendered contrast and accessibility review open until those cases are inspected.

## 2026-11-08 additions

Dark-theme neutrals are brand-derived over hue-neutral anchors: the dark anchors were re-based from green-tinted grays to neutral grays so a non-green organization color tints dark chrome (fixed top bar, heading region, surfaces) with its own hue instead of leaving a green cast; categorical state and accent surfaces keep their semantic hues. Light-theme anchors were already neutral-warm and are unchanged.

The brand lockup (supplied icon + wordmark SVGs, inlined so fills follow tokens) renders the mark and wordmark at equal 34 px height in the sidebar and setup aside, sized for wordmark legibility; the collapsed 68 px rail hides the wordmark and centers the mark. Error feedback uses the warning-triangle glyph in `inline-alert` so state is not carried by color alone; info surfaces keep the help glyph. Category rows, thumbs, and match cards resolve icons through the category's seeded icon field (one shared lookup), covering all seventeen seeded categories.

Window and platform icon usage (2026-11-08): the app icon everywhere is the supplied reclaim mark — `src-tauri/icons/*` is generated from `reclaim-icon.svg` via `pnpm tauri icon`, replacing the stock Tauri icons. On Wayland (this deployment) the compositor resolves the title-bar, taskbar, and Alt-Tab icon from the window's app-id against the icon theme, not from the binary, so the icon is additionally installed under the app-id (`~/.local/share/icons/hicolor/*/apps/reclaim.png` plus a `reclaim.desktop` entry with `StartupWMClass=reclaim`; `enableGTKAppId` is set in `tauri.conf.json`). The dev-server tab uses the same mark as its favicon. This static icon is the fixed brand artwork (teal square, white arrow, amber pin) and intentionally does not follow the organization color — unlike the in-app lockup mark, a platform icon must resolve before the app's own preferences load, and the standard practice is that the product icon stays constant.

## 2026-11-08 owner declutter pass

Overview panels dropped their kickers and subheadings (RECENTLY FOUND / NEEDS ATTENTION / PHOTO GALLERY and their taglines); the quick actions block is headed simply "Quick actions" with two-line-minimum descriptions and brand-derived icon tiles; metric icons likewise follow the brand tokens instead of categorical accents. The workspace area in the sidebar is a static themed identity block (full organization name, no dropdown affordance — Reclaim targets one local workspace), the user row is a single themed line, and the topbar carries only the breadcrumb and the lost-reports shortcut: text-size sizing lives in Settings > Appearance, and the Offline ready/Help chrome was removed. Settings navigation is sticky within the scrolling region. Storage and Retention pages consolidate to a single page-level heading with action/count chips only, and their tables fill the view height with internal scrolling instead of page scrolling.
