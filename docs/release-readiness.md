# Reclaim 0.1.0 release qualification

**Qualification date:** 2026-11-02
**Target:** Linux desktop public beta
**Verdict:** **NOT RELEASE-READY**

**Follow-up after the latest package audit:** The working tree now includes quick-action wrapping, a scrollable focus-contained item drawer, and separate success/error feedback for lost reports and storage. On a Chromium fixture with mocked app data, quick actions fit at 1440×920 and 680×680, the drawer scrolled at the smaller size, keyboard focus remained inside it, and its nested edit dialog and Escape behavior were exercised. The 15 frontend tests, frontend build, design check, and token-level contrast check passed. These checks do not establish native Tauri or screen-reader behavior. Existing package artifacts predate these edits and must be rebuilt and requalified before release.

**Re-evaluated during continuation:** 2026-11-02. The changes and observations in the continuation sections below supersede older task-completion summaries where they conflict. Earlier native QA results remain attributed to their recorded sessions. The 2026-11-02 continuation added native attribution and inventory-query coverage, rebuilt and requalified current-source Debian/RPM packages, and reopened UI qualification because visual and accessibility coverage remains incomplete.

**Development autofill follow-up:** 2026-11-02. The secure-storage sample now clears storage selection if no active secure area is available; a visible placeholder and the required-field rule keep the sample unsavable until staff choose a location. The frontend regression suite passes (16 tests), `pnpm build` succeeds, and the production JavaScript bundle contains none of the development autofill labels or scenario names. This does not qualify native package workflows or screen-reader behavior.

The core workflows have been exercised in the actual Tauri desktop app, including first-run setup, found and lost records, competing-claim adjudication, return verification, archive backup/restore, photo import, and process-restart persistence. Current-source Debian/RPM bundles also passed isolated basic install/start/removal and data-retention checks. The RC is not qualified for public distribution: visual/accessibility, desktop-menu launch, version upgrade, and full installed-package workflows remain incomplete, and no project license has been selected or included.

## Identity, privacy and update policy

Reclaim 0.1.0 is a single-workstation application. The configured operator name is an attribution label, not authentication or authorization. Database files, photos, logos and backups are not encrypted. Keep workstation and backup storage access limited. User-data location observed on this Linux/Tauri runtime: `~/.local/share/com.reclaim.desktop/` (the separate `XDG_DATA_HOME` was not honored by this configured runtime). App updates use packaged releases and SQLite schema migrations; close Reclaim and make a backup before installing the next package. Do not remove the user-data directory during uninstall. Automatic updates are not configured. Tauri's updater requires signed update bundles and a configured public key and endpoint; none are included for this beta.
